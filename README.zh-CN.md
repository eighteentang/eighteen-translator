# 划词翻译（Eighteen Translator）

[![test](https://github.com/eighteentang/eighteen-translator/actions/workflows/test.yml/badge.svg)](https://github.com/eighteentang/eighteen-translator/actions/workflows/test.yml)

[English](README.md) · **中文**

一个 Chrome / Edge 扩展（Manifest V3）：在任意网页选中文字，松开鼠标即可看到译文。

- 全部逻辑在本机运行，不经过任何第三方服务器（除了你选择的翻译引擎本身）
- 浮层用 Shadow DOM 封装，不会被网站自带的 CSS 弄乱
- 两种翻译引擎，在设置页里切换
- **11 种语言**互译（中 / 繁 / 英 / 日 / 韩 / 法 / 德 / 西 / 俄 / 阿 / 泰），方向在本地自动判定（#9）
- 浮层上可以直接**朗读译文**（浏览器自带语音合成，离线）（#10）
- 配置只存在本机，不跨设备同步
- MIT 协议开源

---

## 一、安装（开发者模式加载）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 并回车
2. 打开右上角的 **开发者模式**
3. 点左上角的 **加载已解压的扩展程序**
4. 选择本项目文件夹
5. 安装完成后，点击工具栏里的扩展图标会弹出一个快捷面板

> ⚠️ **首次使用需要在设置页配置翻译引擎** —— 默认引擎是 DeepSeek，需要填一个 API Key；不想申请凭据就把引擎换成 Google 免费接口。
> 首次安装时设置页会**自动打开一次**（升级不会），浮层里的「未配置」提示旁也有一个「去设置」按钮。

> 改了代码之后，回到 `chrome://extensions/` 点一下本扩展卡片上的刷新按钮，再刷新网页即可生效。

## 二、两个入口

| 入口 | 怎么打开 | 放什么 |
|---|---|---|
| **工具栏弹层** | 点击工具栏的扩展图标 | 总开关、触发方式、目标语言、今日用量、主题快捷切换、「在此域名不可用」、去设置页 |
| **完整设置页** | 弹层里点「完整设置」 | 选引擎、填 API Key、选翻译方向、选触发方式、选主题、调浮层字号与宽度、调朗读语速与口音、测试引擎、用量与缓存 |

**分工原则**：弹层只放**高频**操作。引擎、凭据和完整翻译方向等配置仍在设置页里；弹层只提供目标语言的快速调整。

弹层里仍保留一条**红色提醒**：当引擎是 DeepSeek 但还没填 API Key 时出现，告诉你「为什么划词没结果」。引擎选择搬走之后，这是弹层里唯一还能提前告知这件事的地方。

## 三、翻译方向

设置页里选**一对**语言，它们并排放在同一行：

| 字段 | 默认 | 意思 |
|---|---|---|
| **首选语言** | 英文 | 你主要会选中的文字的语言 |
| **目标语言** | 中文 | 你想译成的语言 |

实际翻译时按检测结果决定方向：

| 检测到 | 译成 |
|---|---|
| = 首选语言 | 目标语言 |
| = 目标语言 | **首选语言**（反向） |
| 判不出来 / 其他语言 | 目标语言 |

按默认值（英文 / 中文）跑出来就是：选中英文 → 译成中文，选中中文 → 译回英文。

两个下拉**不能选同一个值**——那样等于不翻译。设置页会当场拦住。

**可选语言共 11 种**（#9）：中文、繁体中文、英文、日文、韩文、法文、德文、西班牙文、俄文、阿拉伯文、泰文。

**语言判定是本地做的**（纯字符统计，不引库、不联网）：

| 判据 | 结果 |
|---|---|
| 出现假名 / 谚文 | 直接定日文 / 韩文（必须先查，否则日文里的汉字会被判成中文） |
| 泰文 / 阿拉伯文 / 西里尔字母**占比过半** | 泰文 / 阿拉伯文 / 俄文（不只看「出现过」——一句英文里引一个俄文词不该判成俄文） |
| 汉字占比 ≥ 50% | 中文；再按「只在繁体 / 只在简体里出现的常用字」细分出**繁体中文** |
| 拉丁字母占比 ≥ 80% | 按**常用虚词**打分细分出英 / 法 / 德 / 西 |

**短于 8 个字符不做判定**，直接按目标语言走。

> 判定一定会判错的时候（中英混排、短句、专有名词）。所以浮层上有个**「译成 X」按钮**：一键换成**当前配置这一对语言里的另一种**，不用跑去设置页改配置。这是误判的出口，不是可选项。
>
> ⚠️ 两条已知的启发式局限（不是 bug，是没有判据）：**简繁**只能靠一张区分字表猜，一段没有区分字的文本（如「今天天气很好」）会判成简体；**拉丁语系**靠虚词打分，一句没有虚词的短句（如「Merci beaucoup」）会判成英文。两种中文都留在下拉里，就是给用户一条自己指定的路。

## 四、界面主题与浮层外观

三档，设置页里选：**跟随系统**（默认）· **浅色** · **深色**。

工具栏弹层右上角还有一个**月亮 / 太阳快捷按钮**，点一下就在浅色与深色之间切换（按钮是两态的，所以要回到「跟随系统」得去设置页）。太阳与月亮叠在同一位置，靠旋转 + 缩放 + 透明度互换，0.42s 的标准缓动——不是「闪一下」，是「转过来」。

主题是**全局的**：弹层、设置页、网页里的划词浮层一起变。系统开了「减弱动态效果」时，旋转会退化成一次极短的淡入淡出。

### 关于外观的两个细节

- **主题按钮做成了「描边 + 底色 + 阴影」的圆形图标按钮**，而不是一个裸图标。裸图标和弹层背景区分不开，用户不知道它可以点。深色模式下黑阴影几乎看不见，所以那一档改用更亮的描边来制造「浮起来」的感觉；按下时还会缩小到 93%，给出「陷下去」的反馈。
- **弹窗窗口本身的圆角由浏览器绘制，CSS 改不了**（Chrome 官方文档口径：这是浏览器 UI 的一部分，没有官方方式能改）。所以「看起来锐利」只能靠**内部元素**跟着变柔和来缓解 —— 卡片圆角 12px、按钮 10px、输入框 9px，弹层与设置页保持一致。

### 浮层字号与最大宽度

网页里那块划词浮层的字号与最大宽度也能调：字号四档，最大宽度三档。

| 项 | 三档 | 默认 |
|---|---|---|
| 字号 | 小 10px · **中 14px** · 大 18px · 特大 24px | 中 |
| 最大宽度 | 窄 320px · **中 420px** · 宽 560px | 中 |

默认档就是改造前写死的 `14px` / `420px` —— 不动它的话，行为与以前**完全一样**。

三点说明：

- **改完立即生效**：不用点保存，也不用刷新已经打开的网页 —— 网页里那块浮层当场就变。
- **宽度是上限，不是固定值**：短句的浮层仍然紧凑（实测短译文约 217px），只有长句才会撑到这一档。窄窗口下调「窄」才不会被浮层挡住。
- 手动模式那颗小圆点**不跟随**字号 —— 它是图标，尺寸就是那个圆的尺寸，不是要读的正文。

实现上，这两个值走 CSS 变量（`--wt-fs` / `--wt-mw`），由 content script 写在**宿主元素的 inline style** 上，而不是页面的 `documentElement` —— content script 不该改宿主页面的任何样式。档位表（哪个档位对应多少像素）在 `config.js` 里，`content.js` 的 CSS 与设置页的下拉读的是**同一张表**，不会出现「下拉里写着 14px、实际是 15px」这种静默不一致。

### 朗读（#10）

浮层工具条上有一个喇叭图标按钮，用于朗读译文。点一下开始读，读的过程中按钮切换为停止图标。

用的是浏览器**自带**的语音合成（`speechSynthesis`）：离线、不上传、不需要任何权限、不需要 Key。

设置页里两项：

| 项 | 三档 | 默认 |
|---|---|---|
| 语速 | 慢 0.8 · **正常 1** · 快 1.25 | 正常 |
| 英语口音 | **跟随系统** · 美式 `en-US` · 英式 `en-GB` | 跟随系统 |

**英语口音为什么值得单列**：`speechSynthesis` 里 en-US 与 en-GB 是两套**独立的声音**（同一台机器上通常都有），所以这是一个真选择，不是摆设。⚠️ 它**只对英语生效** —— 别的语言没有这个区分，设置页里写明了。

几条刻意不做的事：

- **不接云端语音**：朗读使用浏览器内置能力，离线完成。
- **不做暂停 / 继续**：`pause()` / `resume()` 各浏览器行为不一致（Safari 尤其不可靠）。需要的话点停止再点一次重读。
- **不做自动朗读**：每次划词都出声会很烦。
- **不做整页朗读 / 逐句高亮**：那是阅读器，属于另一个产品。

实现上有几个坑写在 `speak.js` 里（每条都会导致**静默失效**）：语音列表是**异步**加载的（首次 `getVoices()` 常常是空数组，要等一次 `voiceschanged`，另加 3 秒兜底）；选音必须按语言过滤再逐层回退，**不能直接用 `getVoices()[0]`**（不同系统上第一条可能是任何语言）；长文本必须分句（单条 utterance 有长度上限，超了后半段会被**静默吞掉**）；切到后台标签页时 `onend` 可能永远不来，所以有一个 18 秒的看门狗强制推进。

⚠️ **很多环境没有可用语音包**（尤其 Linux）。这时浮层会在译文下面**追加**一行说明 —— 而不是 replace 掉整屏（那会把用户刚拿到的译文弄没）。

## 五、选一个翻译引擎

设置页里二选一。

> **本机实测结果（2026-09-23）**
>
> | 引擎 | 结果 | 说明 |
> |---|---|---|
> | Google 免费接口 | **不可用** | 通过代理返回 429，带真实 Chrome UA 后返回反滥用拦截页，换参数返回 403 |
> | DeepSeek | 可达 | HTTP 401（未带 key 时的正常响应），耗时 0.65 秒 |
>
> 因此**默认引擎已设为 DeepSeek**。Google 那个选项仍然保留，换个代理节点后可能恢复。

### 已知限制：Google 免费接口在哪些网络下可用（#5）

这一条是**如实标注**，不是「暂时坏了、以后会修」—— 它取决于你的网络环境，不取决于代码：

| 你的网络 | Google 免费接口 |
|---|---|
| 境外，或自己有条件走干净出口 | **可用** |
| 中国大陆直连 | **不可用** |
| 出口 IP 被限流的代理 | **不可用**（稳定 429） |

**为什么说不是代码问题**：请求 URL 与参数、响应解析（`data[0]` 的分句数组）、429 与非 2xx 的处理、超时（10 秒）都逐环节核对过，与接口实际行为一致（见 #5）。所以本机那个 429 **只说明这台机器的出口 IP**，不说明这个引擎坏掉了。

**已经做过的事**：默认引擎是 DeepSeek（撞上 Google 必须是**主动去选**，不会误伤新用户）；429 有专门文案，明说是**公共接口对共享 IP 的限流**，并给出两条出路（换节点 / 改用 DeepSeek）；设置页那一项下面写着适用网络。

**刻意没做的事**：

- 不删这个引擎 —— 境外用户、或有条件走干净出口的用户，它是**零配置**路径
- 不做「自动探测 Google 是否可用」—— 探测本身也要发请求，而且结果随出口 IP 变，
  只会把一个稳定的事实变成一个飘忽的状态（用户会看到「昨天能选、今天不能选」）
- 不换境内免费源 —— 免费且稳定的翻译接口基本不存在；要注册、有额度上限的，就等于「又一个要配置的引擎」，与它的定位重叠

> ⚠️ **当前开发环境没有验证过「干净 IP 下能返回正常结果」**：此结果会受网络出口影响。
> 结论来自链路逻辑核对，**不声称验证过**。

### 方案 A：DeepSeek（默认，推荐）

1. 打开 DeepSeek 开放平台，注册并登录
2. 左侧菜单进入 **API keys**，创建一个，复制出来（只显示一次）
3. 把 key 填进设置页

- 优点：能结合语境翻译，不是逐词替换；适合长句和技术内容
- 缺点：需要配置自己的 API Key；响应速度取决于网络和服务状态

> 代码里已经显式关闭了 DeepSeek 的思考模式。它默认开启且强度为 `high`，对翻译这种任务只会拖慢速度。

### 方案 B：Google 免费接口

**不用填任何东西。适合境外网络，或自己能走一个干净出口的用户。**

- 优点：零注册、延迟低
- 缺点：**非官方接口**，是公共端点，对共享 IP 的限流很严格 —— 本机实测（2026-09-23，多个节点）稳定返回 429，带真实 Chrome UA 会返回拦截页
- 适合场景：你能访问 `translate.googleapis.com` 且出口 IP 干净时（**判定表见上面那节「已知限制」**）
- **中国大陆网络下不可用**，请用 DeepSeek

> 「不是代码问题」的依据、以及刻意没做的三件事，都写在上面那节「已知限制」里，这里不重复。

### 用量、每日上限与缓存

设置页底部有一节「用量」，三行：

| 行 | 内容 |
|---|---|
| 今日已翻译 | 本机日期下的次数 |
| 每日上限 | 到上限后当天不再发请求。右边是「调高上限」按钮 |
| 译文缓存 | 已缓存的条数。右边是「清空缓存」按钮 |

**上限为什么不做成输入框、也不显示数值**：它是一道**防误触保护**。页面上只有一个「调高上限」按钮，点一下往上加一档，**不回显新数值**。真到上限时，「今日已翻译」变红、下面那行说明改成「今天已经到上限了」，网页里的浮层也会给出一个「去设置」。

> 计数点是**请求发出时**，不是成功后。这样设置页显示的次数与实际拦截请求使用同一个口径；被取消的请求也会被记录。

**译文缓存**（同样的内容不重复请求）：

- 键是 `引擎 + 目标语言 + 原文`。**引擎和方向都必须进键** —— 否则改完设置会拿到上一次的旧译文，而且是以「改了设置不生效」的形式暴露，最难查
- 命中缓存**既不发请求、也不计次数**：反复划同一个词不会增加次数
- 最多 200 条、7 天过期，按「最久未用」淘汰；单条**译文**超过 2000 字符不缓存（量的是译文不是原文 —— 占存储的是值，键是定长散列）
- ⚠️ **缓存命中优先于凭据检查**：命中就不发请求，所以没填 API Key 也能拿到已缓存的结果

**用量只保留最近 30 天**，这个键不会随使用无限膨胀。

## 六、怎么用

- 在任意网页**选中文字 → 松开鼠标**，选区旁会出现浮层显示译文
- 浮层上的按钮：**复制**（复制译文）、**关闭**
- 关闭方式：点「关闭」、按 `Esc`、点击页面空白处
- 页面滚动时浮层会跟随选区
- 浮层永远贴着选区、且**不盖住选区**；贴到视口边缘时自动换边
- **跨行选中时按「首行」对齐**，不是按整段的中间 —— 整段的包围盒取的是最长那一行，
  拿它居中会让浮层跑到段落中间，而你的眼睛在起手那一行
- **改窗口大小（或手机旋转）不会关掉浮层**，它会按新尺寸重新定位
- 选中的文字超过 **1000 字符**不会翻译，浮层会说明「选中了 N 个字符、超过上限」——
  以前这里是静默无反应，容易让人以为插件坏了。**长文请分段选**（分片翻译没做，见「未做的部分」）
- 纯数字、纯符号不会触发翻译
- 选中**代码 / 链接 / 邮箱 / 文件路径 / 命令行**不会翻译，浮层会说明拦的是什么，
  并给一个「仍然翻译」—— 见「常见问题」。这一项可以在设置页关掉
- 等待时浮层显示「翻译中」加三个跳动的小点；超过 **3 秒**还没结果，会补一句「请稍候」——
  那是用户开始怀疑「是不是卡死了」的时刻
- **失败之后不用重新划词**：网络不通 / 超时 / 引擎报错这几类，错误下面有一个「重试」
- 在**嵌入的 iframe 里**，如果那个框太小（宽 < 320 或高 < 220），不生效也不发请求 —— 见「常见问题」

### 自动与手动

设置页里二选一：

| 模式 | 行为 |
|---|---|
| **自动**（默认） | 选中文字、松开鼠标就翻译 |
| **手动** | 选中后只在旁边出一颗小圆点，点它才翻译 |

**手动模式不会自动发请求**：选中后只有点击小圆点才会开始翻译。

那颗圆点是 24px 的圆形按钮，有描边、有阴影 —— 参考弹层主题按钮那次的教训：
裸图标和网页背景分不开，用户根本不知道那儿有个东西。点别处或按 `Esc` 收起。

### 哪些站点不翻译（排除站点）

两个入口，改的是**同一份列表**：

| 入口 | 怎么用 |
|---|---|
| 工具栏弹层 | 勾上「**在此域名不可用**」—— 当前域名就进了排除列表 |
| 设置页 → 排除站点 | 一行一个域名，可手工编辑 |

匹配规则（写域名就行，不用写协议和路径）：

| 写法 | 命中的 |
|---|---|
| `example.com` | `example.com` 与它的所有子域（`a.example.com`、`a.b.example.com`） |
| `*.example.com` | 同上 —— `*.` 只是把意图写清楚，语义完全一样 |
| `intranet` | 单段主机名，公司内网那种 |
| `# 备注` | 以 `#` 开头的是备注，不参与匹配 |

**粘贴整条网址也可以**（`https://mail.google.com/mail/u/0?x=1` 会当成 `mail.google.com`）。
**不支持正则**；`*` 只能写在最前面 —— 写成 `foo.*.com` 会被当成格式错误报出来，
而不是当成字面量（字面量永远不会命中，那才是真的坑）。

后缀匹配**卡住点号边界**：`example.com` 不会命中 `notexample.com`，
也不会命中 `example.com.evil.com`。

三点要记住：

- ⚠️ **改完要刷新已打开的标签页。** 判断只在页面加载时做一次 —— 这正是它几乎不花性能的原因。
  设置页保存后会明确提示，弹层里勾完也会提示。
- ⚠️ **内容脚本仍然会被注入**，只是注入之后什么都不做（不注册划词监听、不建浮层、不发请求）。
  真正「不注入」需要改成动态注入，那会失去「选中即翻」的自动性，不划算。
  所以这里说的是「不翻译」，不是「不注入」。
- 想让**所有**站点都不生效，请用总开关，不要在列表里写 `*`（会被判成格式错误）。

## 七、常见问题

**选中后没有任何反应**

1. 先确认弹层或设置页里「启用划词翻译」是开着的
2. 再确认这个域名**不在排除列表里** —— 弹层里那个「在此域名不可用」勾选框就能看出来
3. 到 `chrome://extensions/` 点本扩展的刷新按钮，然后**刷新网页**（必须刷新，否则旧的内容脚本还在跑）
4. 有些网站的阅读器模式或 PDF 阅读器里拿不到选区，属于浏览器限制

**点击工具栏图标没有反应**

八成是扩展没重新加载。**重新加载扩展后，已经打开的网页里跑的还是旧脚本 —— 旧脚本的事件监听已经失效，所以划词不会有任何反应**，点图标也不会弹面板。必须刷新网页。

顺带一提：v0.1.0 的清单里图标点击**没有绑定任何行为**（既没有弹层，也没有 `action.onClicked` 监听），所以那个版本点图标本来就是没反应的。如果点图标还是没动静，先到 `chrome://extensions/` 确认卡片上显示的版本号是 **0.3.1** 或更高。

**想确认自己加载的是哪一版**

点工具栏图标，弹层顶部会显示版本号（如 `v0.4.1`）；设置页的页脚也有一份。也可以在 `chrome://extensions/` 的卡片上直接看。

**浮层提示「扩展未就绪」或「扩展上下文已失效」**

扩展重新加载后，已经打开的网页里跑的还是旧脚本。刷新那个网页即可。

**提示网络请求失败**

- 用 Google 引擎：确认代理已开启且浏览器确实走代理。如果返回 429，说明这个公共接口对你的出口 IP 限流了——换个节点，或改用 DeepSeek。**中国大陆网络下这个引擎本来就用不了**，见第五节那节「已知限制」
- 用 DeepSeek：确认网络正常，以及设置页里的 API Key 填对了

**翻译失败之后，只能重新划一次词吗**

不用。网络不通、超时、引擎报错这几类失败，错误文案下面有一个**「重试」**，
点它就用**同一段原文**再发一次，连方向都保持上一次的。

但「没填 API Key」和「到了每日上限」这两种**不给**重试 ——
那得先去设置页解决，重试一百次结果也一样。

**一直显示「翻译中」，是不是卡死了**

浮层上那三个点在跳，说明请求还在。超过 3 秒会补一句「请稍候」。
DeepSeek 在高峰期确实可能要几秒；超过它自己的超时（Google 10 秒 / DeepSeek 25 秒）
就会转成明确的超时提示，不会一直转下去。

**翻译报错**

把浮层上的完整报错文字发我，我按错误码定位。

**昨天还好好的，今天划词没反应了**

先看浮层的提示是不是「今日翻译次数已用完」。这是**每日上限**（默认 500 次）在起作用 ——
到设置页的「用量」一节，点「调高上限」即可继续。它是一道防误触保护：
正常使用基本碰不到，会被它挡住通常是「反复划同一个词」或网页脚本误触发。

**改了设置不生效**

设置是即时生效的，但如果页面在改设置之前就打开了，建议刷新一次页面。

**同样的句子，为什么第二次几乎瞬间出结果**

因为它命中了**译文缓存** —— 不会再请求引擎，所以更快，也不计次数。
缓存键里含引擎与翻译方向，所以这两项一改就会自动失效；想强制重新翻，
到设置页的「用量」一节点「清空缓存」。

**API Key 存在哪里，安全吗**

以**明文**存在本机浏览器的扩展存储（`chrome.storage.local`）里 —— **不加密、不上传**。
**本插件无云端存储，本地电脑请自行保管**：能读到浏览器配置目录的人就能看到它。
设置页那个「显示 / 隐藏」只是遮住屏幕，不是加密（扩展里做本地加密没有意义：密钥只能一起放在扩展里，等于没加，反而给人虚假的安全感）。

**换台电脑要重新配置吗**

要。**配置只存在本机，不随浏览器账号同步** —— 这一条是刻意的：核心配置里有 API Key，一旦同步，用户会以为「登同一个账号就能拿到我的 Key」，而同步的数据实际存在 Google 账号里，对国内用户既不可用也不可解释。

**在嵌入的 iframe 里划词没反应**

如果是**尺寸很小**的 iframe（宽 < 320 或高 < 220），这是刻意不生效的。
浮层挂在 iframe 内部、以 iframe 自己的视口为基准定位，**装不下就会被 iframe 的盒子裁掉** ——
与其让用户看到一个「时好时坏的怪现象」，不如明确不做，并且连请求都不发。
⚠️ 判断只在页面加载时做一次，iframe 事后被拉大需要**刷新页面**才恢复。

**选中了很长一段，浮层说超过上限**

上限是 1000 字符（避免误选整页）。分片翻译（一次划词切成 N 次请求）**没做** ——
目前请分段选。

**选中文字后只出现一颗小圆点，不出译文**

这是**手动模式**（设置页 →「触发方式」）。点那颗圆点才翻译，点别处或按 `Esc` 收起。
想回到「选中即译」，把触发方式改回「自动」。

**选中一段代码 / 一个链接，浮层说「已跳过翻译」**

这是刻意的（#60）：读技术文档时随手选到一段代码、一个 URL，翻出来只是把原文回一遍，
没有翻译价值又会干扰。判定的五类内容是 **代码 / 链接 / 邮箱 / 文件路径 / 命令行**，
而且**只在短于 200 字符的选区上判定** —— 长文里夹一行代码时跳过整段，才是真正的误伤。

判定是启发式的，**一定会误伤**（比如「他说：{引用的内容}」）。所以浮层上始终有一个
**「仍然翻译」**。嫌误伤多的话，到设置页把「跳过技术内容」关掉，就完全回到旧行为。

**六个共享模块，都是「无构建、双模式加载」**：`config.js` / `strings.js` / `lang.js` / `theme.js` / `tech.js` / `sites.js` —— service worker 用 `importScripts`、content script 靠 manifest 里的加载顺序、设置页和弹层用 `<script src>`（`theme.js` 要放 `<head>` 里防首帧闪）、Node 自测用 `require`。**加配置项只改 `config.js`，改文案只改 `strings.js`，加语言只改 `lang.js`，改技术内容判定只改 `tech.js`，改排除站点规则只改 `sites.js`**，不要往别的文件里塞拷贝。

> ⚠️ `tech.js` 是唯一的例外：**只有 content script 加载它**。设置页与弹层只负责存那个开关、不做判定，所以这两个页面不加载 —— 这是有意的，不是漏了。
>
> ⚠️ `speak.js`（#10）同理：**只有 content script 加载它**（朗读按钮在浮层上）。
> 它**不是**双模式共享模块 —— 目前只有一处用得到，做成四宿主共用的形态是过度设计；
> 将来设置页要做「试听」时再升级。但它仍然**必须排在 `content.js` 之前**，
> 否则 `globalThis.WT_SPEAK` 是 `undefined`，朗读功能整段静默失效（`dev/check.js` 会挡）。

> ⚠️ 往 manifest 的 `content_scripts.js` 里加共享模块时，**顺序不能错**：必须在 `content.js` 之前，否则 `content.js` 里读 `globalThis.WT_*` 会拿到 `undefined` 而整段脚本静默失效。

### 文案：一个文件，一处改（#39）

用户可见的每一句话都在 `strings.js` 里：`STRINGS = { zh: {...}, en: {...} }`，取用一律走 `t('key')`。HTML 里不写文案、只写 `data-i18n="key"`，加载时由 `applyI18n()` 填上（连 `title` / `aria-label` / `placeholder` 三个属性一起填）。

几条刻意定下来的规矩：

| 规矩 | 为什么 |
|---|---|
| 缺键时**返回键名**，绝不返回空串 | 空串是最坏的结果：界面上少一句话，没有任何痕迹，也没人会发现。返回 `opt.secUsage` 至少一眼看得出缺了一条 |
| 缺键先**回退中文** | 英文表漏一条时，宁可中英混一句，也不能让整句话消失 |
| 文案一律在**渲染 / 发送的那一刻**取，不做模块级快照 | 快照会把浮层与后台的错误文案锁死在脚本加载时的语言上，切完语言只对新页面生效 |
| `innerHTML` 只用于**静态文案**，用户数据一律 `textContent` | 说明文案里夹着 `<b>` / `<code>` / `<br>`，所以只能走 innerHTML；这条界限糊了就是一个注入口 |
| HTML 先藏住（`html.i18n-pending`），填完再显示 | 否则会先闪一下空标签 |
| 例外必须显式标 `i18n-allow: 理由` | 提示词（给模型看）、CSS 模板串里的注释、按语言码分键的测试样本这三类**故意**不是界面文案；不标就等于硬编码 |

`dev/scan-i18n.js` 就是查这个的：把源码按「块注释 / 行注释 / 字符串 / 正则」四种状态走一遍，找出字符串字面量里的汉字。**没有拿正则糊一遍** —— 正则字面量里会出现引号和反引号（`tech.js` 的 `RE_UNIX_PATH` 就带 `"` 和 `'`），不认出来会把后面整段代码吞进「字符串」里，命中与漏报全乱。HTML 那一侧同理，剥掉注释与 `<style>` / `<script>` 之后连属性一起查 —— `popup.html` 的 `aria-label="切换主题"` 就是这么漏出来的。

> ⚠️ `manifest.json` 的 `name` / `description` **没法由 JS 改**，抽不进 `strings.js` —— 它们只能走 `_locales` + `__MSG_xxx__`，见 #56。

### 界面语言：能手动切，但名字不跟着切（#35 / #56）

这里有两套机制，**刻意不合并**：

| | 界面文案（设置页、弹层、浮层提示） | 扩展名与商店描述 |
|---|---|---|
| 数据在哪 | `strings.js` | `_locales/<locale>/messages.json` |
| 语言由谁定 | **用户自己选**（跟随浏览器 / 中文 / English） | **浏览器语言**，扩展无法覆盖 |
| 能不能手动切 | 能 | 不能 |
| 为什么 | 用户可能想用英文界面读中文网页 | manifest 的字符串只能走 `__MSG_xxx__` |

所以会出现「界面是英文、扩展名字还是中文」—— 这是**刻意的**，设置页的「界面语言」那一节里写明了，免得用户以为坏了。

- 设置页的「界面语言」是三档（跟随浏览器 / 中文 / English），改完**立即生效、立即保存**，与主题同一个做法。
- 工具栏弹层右上角有一个 `EN` / `CN` 小胶囊，是同一个开关的快捷方式，与主题按钮并排。
  ⚠️ 上面那两个字**刻意不翻译**：中文界面显示 `EN`（点一下切到英文），英文界面显示 `CN`。
  它要是一起翻译了就会**自指** —— 中文界面里写着「英文」，用户根本不知道点下去会发生什么。
  提示文字（`title` / `aria-label`）则跟着当前语言走，它描述的是「这个动作」，不自指。
- 存的是**偏好**（`auto` / `zh` / `en`）而不是解析结果 —— 存成 `zh` 的话，用户换了浏览器语言就永远回不到「跟随」了。
- 「跟随浏览器」只认中英两种；浏览器是第三种语言（法、德、日…）时给**英文**，不是中文 ——
  给一个法国用户看中文界面比给英文更糟。而 `strings.js` 的 `DEFAULT_LANG`（缺键时回退到哪张表）仍然是中文，那是另一件事。
- ⚠️ **切语言时要重画的不只是静态文案**：设置页里三个下拉的选项文字也是 `t()` 出来的，
  漏刷任何一处就会停在「页面是英文、下拉里还是中文」这种半截状态 —— 而这在源码里完全看不出来。e2e 里专门钉了这条。

### 加一门翻译语言要动四处（#9）

`lang.js` 的 `LANGS` 是**语言表**，但它只写了语言码 —— 加一门语言实际要改四处，漏一处**都不会报错**：

| 改哪 | 漏了会怎样 |
|---|---|
| `lang.js` 的 `LANGS` | 下拉里没有这门语言（这条漏了最明显） |
| `strings.js` 的 `lang.<code>`（zh / en 各一条） | 下拉里显示的是**键名本身**（`lang.xx`） |
| `background.js` 的 `LANG.google` | Google 引擎静默换成 `zh-CN`，出来的还是中文 |
| `background.js` 的 `PROMPT_NAME` | 提示词里写的还是 `target` 这个码，模型表现不稳 |
| `options.js` 的 `SAMPLE` | 「测试翻译」静默退回中文样本 |

> ⚠️ **语言表 ≠ 界面语言表**：能翻译的有 11 种，但界面文案只有 `zh` / `en` 两张表。
> 设置页的「界面语言」下拉走 `strings.js` 的 `UI_LANGS`（由 `STRINGS` 的键推出来，加一张文案表就自动多一档），
> **不是** `lang.js` 的 `LANGS` —— 混用的话，加一门翻译语言会往界面语言下拉里塞进没有文案的语言，选了它界面会静默回退成中文。

> ⚠️ 判定也是要跟着改的：`detect()` 里泰文 / 阿拉伯文 / 西里尔文各有专属字符，好认；
> 但**同是拉丁字母的法 / 德 / 西**只能靠虚词打分细分。加一门拉丁语系的语言时，
> 要在 `LATIN_WORDS` 里补一张虚词表 —— 不补的话它会一直判成英文，
> 配上「首选中文 / 目标法文」就会绕回「译成同语言」那个 bug（#2 修过一次，从另一个门又进来）。

> ⚠️ 商店对扩展名的**标题另有 45 字符的上限**（manifest 本身允许 75）。`dev/check.js` 会在
> 名字超过 45 字符时给一条提示 —— 不报错（扩展本身合法），但上架时会被拒或被截断。

> 抽文案那一步（#39）**刻意不改任何默认行为**：默认语言仍是中文。
> 默认值改成「跟随浏览器」是下一步（#35）做的，也是整个改造里**唯一**一处默认行为的改变 ——
> 浏览器是英文的用户装上来就是英文界面，这是面向国际用户的本意，但它确实是个行为变更。

**跑自检**（纯 Node、零依赖，CI 里跑的第一条就是它）：

```bash
node dev/check.js
```

它查五项 —— 都是**踩过一次就不再想踩第二次**的坑：

| 查什么 | 为什么 |
|---|---|
| 扩展目录里以 `_` 开头的文件 / 目录（`_locales` / `_metadata` 除外） | Chrome 的保留名，会**直接拒绝加载**；而且与是否被 manifest 引用无关 |
| manifest 引用但不存在的文件 | 漏一个就是「加载了但某处不工作」 |
| manifest 字段体检（必填项 / 版本号 `x.y.z` / description ≤ 132 / `host_permissions` 与实际请求的域名一致） | 版本号写错会让更新推不上去；权限对不上会被审核问 |
| `content.js` 读到的每个 `globalThis.WT_*`，其定义文件必须排在 `content.js` 之前 | 顺序错了会拿到 `undefined`，**整段脚本静默失效** —— 五项里最容易被无声破坏的一条 |
| `_locales` 与 `__MSG__`（#35 / #56） | 漏 `default_locale` **直接加载失败**；目录名写成 `zh-CN` 被静默忽略；某个语言少一个键就悄悄退回默认语言；description 超长要等上架才知道 |

发现任一项即**非零退出**。要确认它不是个「永远通过」的摆设，可以跑负向测试：

```bash
bash <工作目录>/check-negative.sh
```

它会复制一份扩展、**故意弄坏 17 种方式**（含上面每一项），逐个跑 `check.js` 看是否真的非零退出。

> ⚠️ 这个负向测试原来是一份 Node 脚本，而本机环境下 Node 里 spawn 子进程会 EBUSY ——
> 也就是说它**从来没真正跑过**：子进程没起来，`e.status || 1` 恰好也等于 1，
> 于是每次都打印「CAUGHT」。现在改成 bash（由 shell 去发子进程），并补上了
> 「哪一条 ✗ 被抓到」的输出。**一个永远通过的负向测试比没有更糟** —— 它会让人以为防线在。

**跑自测**（需要 Node，不影响扩展本身）：

```bash
node dev/selftest.js
```

它会 mock 掉 chrome API 和网络请求，验证引擎调度、凭据缺失处理、各类错误提示、`quotaMode` 的分支行为、**连划时的请求取消**、**语言判定与翻译方向**、**首次安装引导**、**触发方式的默认值**、**技术内容判定的五类样本与「不许误伤」样本**、**浮层字号/宽度档位表（默认档与改造前一致、认不出的档位退回中间档、id 不重复）**、**排除站点的匹配规则（后缀匹配卡点号边界、粘贴网址的规范化、写错的行带行号、增删时保留备注）**、**每日上限拦截**、**用量计数与 30 天裁剪**、**结果缓存（命中不计数 / 换引擎与换方向不命中 / 超长译文不入缓存）**、**文案表（zh / en 键完全一致、插值、缺键返回键名、英文缺键回退中文、认不出的语言码退回默认、每个档位 / 语言 / 技术类别都有对应文案、`applyI18n` 的四个选择器、后台错误文案跟着语言走、源码里不再有中文硬编码）**、**界面语言的解析（明确指定 / `auto` 跟随浏览器 / 浏览器是第三种语言时给英文 / 认不出的偏好退回默认 / 没有 `chrome.i18n` 时不抛）**、**语言扩展（新语言的判定细分含拉丁语系、俄文词占比门槛、简繁字表等长且不相交、`other()` 按配置的一对语言切、界面语言表不跟着翻译语言一起长、每个语言的 Google `tl` 与提示词名、样本句覆盖每门语言）**、**朗读（语速档位表、分句认中英文标点、超长句二次切分、选音按语言过滤 + 本地优先 + 系统默认优先、`canceled` 不算错误、状态机逐句推进与停止、看门狗、没有语音包时 `start()` 返回 false）**，共 123 项。

> mock 里把「配置」与「持久存储」分开成两份：配置每个用例都要换一份，而用量与缓存必须跨用例累积，才能测出「第二次命中缓存」「到顶被拦」。混在一起的话，上一个用例写进去的配置会串到下一个用例的 `get(null)` 上。

> ⚠️ `selftest.js` 必须留在 `dev/` 子目录里。Chrome 不允许扩展目录中出现以 `_` 开头的文件名（`_locales`、`_metadata` 除外），一旦改名成 `_selftest.js` 放回根目录，扩展会**直接拒绝加载**。这条现在由 `dev/check.js` 自动挡（连子目录一起查），不用再靠记忆。

## 九、图标

设计：圆角方底 + 简化地球（外圈 + 两条经线 + 一条赤道）+ 字母 `A` + 右上角四角星。
字母和星星底下都描了一圈底色做留白，把穿过它们的经纬线推开，否则经纬线会横切字面。

**为什么有两个源文件：**

| 源文件 | 用途 | 说明 |
|---|---|---|
| `icons/icon.svg` | 32 / 48 / 128 | 完整版：地球 + 经纬线 + A + 星 |
| `icons/icon-16.svg` | 16 | 简化版：去掉全部经纬线，外圈降到 60% 不透明度，A 放大加粗 |

16px 单独做一版是必须的：完整版缩到 16px 时，白色外圈和白色字母之间只隔约 1px，
两者会粘成一团白块，字母认不出来（放大 8 倍复核过）。而**工具栏和扩展列表用的正是 16px**。

所有几何都是手写路径，不依赖任何字体 —— 换台机器渲染结果完全一致，
不会因为系统缺少某个字体而静默退化成别的样子。

**重新导出**（改了 SVG 之后跑）：

```bash
npm i puppeteer-core                    # 任意目录
export NODE_PATH=<那个目录>/node_modules
node dev/export-icons.js                # 导出 4 个 PNG 并校验
node dev/export-icons.js --preview      # 额外出 8 倍放大检查图和明暗底预览图
```

脚本会自动探测本机的 Chrome / Edge，也可以用 `WT_BROWSER=<可执行文件路径>` 指定。
导出后会逐张校验：真实像素尺寸、圆角之外是否透明、不透明像素占比是否正常。

> manifest 只认 PNG 不认 SVG，所以改了 `icons/*.svg` 必须重跑这个脚本，否则改动不会生效。

## 十、端到端验证浮层

`dev/selftest.js` 用 mock 测后台逻辑，测不到「浮层到底有没有出现」——
那需要真实浏览器、真实扩展加载、真实 DOM。这个脚本补这一段：

```bash
node dev/e2e-panel.js
```

它会起一个本地 http 服务、用无头 Chrome / Edge 加载未打包扩展、建立选区、
然后逐条断言：内容脚本有没有注入、浮层宿主有没有插入 DOM、`display` 是不是 `block`、
有没有落在视口内、中心点能不能被命中（会不会被页面盖住）、滚动跟不跟、
`Esc` 关不关得掉、超长选区**给出说明而不是静默无反应**、连划时旧请求会不会被取消、
**未配置凭据时错误旁有没有一个可点的「去设置」**、**点「复制」会不会真的变成「已复制」**、
主题按钮点一下会不会真的翻转、改 storage 后浮层跟不跟随、
主题按钮**是不是真的像个按钮**（有描边、有底色、且底色与弹层背景不同）、
设置页那两个下拉是不是**真的并排同一行**（量上边缘，不靠目测）、
**凭据有没有显示 / 隐藏切换、有没有写明它是明文存的**、**有没有写明配置只存本机**、
**反馈入口有没有带 issue 模板、诊断信息会不会泄漏 Key**、
**设置页的用量一节（调高上限真的改了存储、清空缓存真的清了、上限数值不出现在页面上）**、
**技术内容被拦下时一个请求都没发出去、且「仍然翻译」点了之后请求照发**、
**手动模式下选中只出小圆点（不发请求）、圆点直径与描边量得出来、点了才发请求**、
**等待态有三个跳动的点、超过 3 秒补一句「请稍候」、失败后「重试」真的重发一次**、
**改窗口尺寸后浮层重新定位而不是关掉、跨行选区按首行对齐、贴边时换边、浮层不盖住选区**、
**改浮层字号/宽度后已打开的浮层当场跟着变（不刷新页面）、变量写在宿主元素上没污染页面、宽度真的卡在上限**、
**浮层上有朗读按钮、点了有反应（进入朗读态或给出可读提示）、没有这门语言的语音包时说得出原因、提示不会把译文顶掉**、
**排除站点上划词连浮层宿主都不建、一个请求都不发（去掉之后刷新就恢复）**、
**popup 的「在此域名不可用」勾选框（内容脚本回答域名、拿不到时置灰、勾上真的写进同一份列表）**、
弹层里**确实已经没有引擎选择**、反馈建议链接指向 GitHub Issues、开关联动对不对、
**两个页面的文案是不是真的由 JS 填上的（`i18n-pending` 已撤、73 个节点一个不空、切英文再切回来真的跟着变）**、
**弹层右上角那个 EN / CN 按钮点一下整页换语言（按钮上的字刻意不翻译）、设置页切语言时三个下拉的选项文案也一起跟着变（不会停在半截语言）、切完不会把别的下拉重置掉**、
**`_locales` 里的名字与描述真的被 `chrome.i18n` 读到（占位符写错一个字母时，Chrome 会把 `__MSG_extName__` 原样显示出来 —— 而扩展照样能加载）**、
**设置页的翻译方向下拉真的有 11 种语言、显示的是语言名而不是语言码（漏补一条文案时 t() 会把键名原样返回）**、
**朗读按钮点了有反应、没有这门语言的语音包时真的说得出原因、提示不会把译文顶掉**。共 110 项。

> 「连划时旧请求会不会被取消」这一段的做法：给 service worker 装一个假 key 让请求真的走到 `fetch`，
> 再把 `fetch` 换成永不返回的探针 —— 正好复现「上一次还在生成、用户又划了一次」。
>
> 「看起来像不像按钮」这类判断也用计算样式断言（`border-top-width`、`box-shadow`、`background-color`），
> 但**断言只能证明属性变了，证明不了手写的 SVG 没画歪** —— 涉及图标和布局时仍然要截图看一眼。
> 这样能验到 `selftest.js` 验不了的东西：`close()` 到底有没有**主动**把 cancel 发出去。

> 两个反直觉的坑，写测试时容易踩：
> 1. **不能用 `page.evaluate` 查 `chrome.runtime` 判断内容脚本是否注入。** `page.evaluate` 跑在页面主世界，内容脚本在隔离世界，主世界看不到 `chrome.runtime`。要监听 CDP 的 `Runtime.executionContextCreated`。
> 2. **点浮层中心时，`document.elementFromPoint` 返回的是宿主元素**，不是 shadow 内部元素。用 `el.getRootNode().host` 判断会永远失败（宿主的根节点是 `document`，`document` 没有 `.host`）。

## 十三、发版（版本号 · CHANGELOG · 打包）

### 版本号是三处对齐的（#42）

**`manifest.json` 的 `version` 是单一真源**，另外两处跟着它走：

| 位置 | 规则 |
|---|---|
| `manifest.json` 的 `version` | `x.y.z` 三段（Chrome 不接受四段） |
| git tag | `v` + 同一个版本号（如 `v0.4.1`），打在发布提交上 |
| `CHANGELOG.md` | 顶部第一条就是当前版本，与 tag 同一次提交 |

| 段 | 什么时候 +1 |
|---|---|
| `z` | 修 bug、改文案 |
| `y` | 加功能 |
| `x` | 破坏性变更（改配置键、改存储结构） |

⚠️ **`y` 与 `x` 的区别对升级用户很重要**：`0.4.0` 改过 `targetLang` 的语义并因此写了迁移逻辑 ——
老配置会被自动改写成新语义。这类改动必须让人一眼看出来。

```bash
node dev/check-version.js
```

它查 `manifest.json` 的版本与 `CHANGELOG.md` 顶部是否一致、版本标题格式对不对、有没有重复。
**这条约定靠自律维护会在第三次发版时失效**，所以已经接进 CI。

### 打包

```bash
node dev/pack.js
```

产出 `dist/eighteen-translator-v<版本号>.zip`，可直接上传商店。

它是**白名单**打包 —— 只收「manifest 引用到的文件 + HTML 页面里引用到的文件 + `icons/` + `_locales/`」，
`dev/`、`docs/`、README 与 LICENSE 都进不去。黑名单的问题在于：将来新增一个开发文件，
忘了加进忽略列表就会**悄悄进包**；白名单相反，新文件默认不进包。

> ⚠️ **HTML 那一层不能漏**：`options.js` / `popup.js` 只被 `options.html` / `popup.html` 的
> `<script src>` 引用，**manifest 里根本看不到它们**。只按 manifest 收，打出来的包一装就是「设置页空白」。

脚本会**把 zip 读回来逐条解压、与源文件逐字节比对**再报成功 —— 结构合法还不够，
得证明内容真能还原（deflate 写错、CRC 写错都在这一步暴露）。
想再验一层「装上去能不能跑」：

```bash
WT_EXT_DIR=<把 zip 解到的目录> node dev/e2e-panel.js
```
