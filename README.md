# 划词翻译

一个 Chrome 扩展（Manifest V3）：在任意网页选中文字，松开鼠标即可看到译文。

- 全部逻辑在本机运行，不经过任何第三方服务器（除了你选择的翻译引擎本身）
- 浮层用 Shadow DOM 封装，不会被网站自带的 CSS 弄乱
- 两种翻译引擎，弹层或设置页里切换
- 配置只存在本机，不跨设备同步
- MIT 协议开源

---

## 一、安装（开发者模式加载）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 并回车
2. 打开右上角的 **开发者模式**
3. 点左上角的 **加载已解压的扩展程序**
4. 选择本文件夹（`D:\eighteentang-translator`）
5. 安装完成后，点击工具栏里的扩展图标会弹出一个快捷面板

> 改了代码之后，回到 `chrome://extensions/` 点一下本扩展卡片上的刷新按钮，再刷新网页即可生效。

## 三、选一个翻译引擎

设置页里二选一。

> **本机实测结果（2026-09-23）**
>
> | 引擎 | 结果 | 说明 |
> |---|---|---|
> | Google 免费接口 | **不可用** | 通过代理返回 429，带真实 Chrome UA 后返回反滥用拦截页，换参数返回 403 |
> | DeepSeek | 可达 | HTTP 401（未带 key 时的正常响应），耗时 0.65 秒 |
>
> 因此**默认引擎已设为 DeepSeek**。Google 那个选项仍然保留，换个代理节点后可能恢复。

### 方案 A：DeepSeek（默认，推荐）

1. 打开 DeepSeek 开放平台，注册并登录
2. 左侧菜单进入 **API keys**，创建一个，复制出来（只显示一次）
3. 充值（按量计费）
4. 把 key 填进设置页

- 优点：能结合语境翻译，不是逐词替换；境内直连稳定；注册流程最快，不需要实名认证
- 缺点：需要充值；响应比专用翻译接口慢（1–2 秒）

**成本参考**（依据 DeepSeek 官方定价页的 `deepseek-flash` 模型）：一次划词大约消耗 100 输入 + 50 输出 tokens，单次成本约 **0.0003–0.0006 元**。按每天 100 次计算，一个月不到 2 元。

> 官方定价分高峰与低峰，**低峰是半价**。高峰时段为 UTC 01:00–04:00 与 06:00–10:00 的工作日，换算成北京时间是 **工作日 09:00–12:00 与 14:00–18:00**，其余时间（含全部周末与节假日）都按低峰计价。

> 代码里已经显式关闭了 DeepSeek 的思考模式。它默认开启且强度为 `high`，对翻译这种任务只会拖慢速度。

### 方案 B：Google 免费接口

**不用填任何东西，但当前网络环境下用不了。**

- 优点：零注册、零成本、延迟低
- 缺点：非官方接口，对共享代理 IP 限流严格（本机实测稳定返回 429）；境内必须依赖代理
- 适合场景：你换到一个干净的代理节点、且确认能访问 `translate.googleapis.com` 时

## 四、怎么用

- 在任意网页**选中文字 → 松开鼠标**，选区旁会出现浮层显示译文
- 浮层上的按钮：**复制**（复制译文）、**关闭**
- 关闭方式：点「关闭」、按 `Esc`、点击页面空白处
- 页面滚动时浮层会跟随选区
- 选中的文字超过 1000 字符不会翻译（避免误选整页）
- 纯数字、纯符号不会触发翻译

## 五、常见问题

**选中后没有任何反应**

1. 先确认弹层或设置页里「启用划词翻译」是开着的
2. 到 `chrome://extensions/` 点本扩展的刷新按钮，然后**刷新网页**（必须刷新，否则旧的内容脚本还在跑）
3. 有些网站的阅读器模式或 PDF 阅读器里拿不到选区，属于浏览器限制

**浮层提示「扩展未就绪」或「扩展上下文已失效」**

扩展重新加载后，已经打开的网页里跑的还是旧脚本。刷新那个网页即可。

**提示网络请求失败**

- 用 Google 引擎：确认代理已开启且浏览器确实走代理。如果返回 429，说明这个公共接口对你的出口 IP 限流了——换个节点，或改用 DeepSeek
- 用 DeepSeek：确认网络正常，以及设置页里的 API Key 填对了

**翻译报错**

把浮层上的完整报错文字发我，我按错误码定位。

**改了设置不生效**

设置是即时生效的，但如果页面在改设置之前就打开了，建议刷新一次页面。

## 六、文件说明

```
manifest.json     扩展清单（MV3），声明权限、后台脚本、内容脚本、弹层
config.js         共享配置：DEFAULTS 的单一真源，四种宿主共用（无构建步骤）
background.js     后台服务：按配置调用翻译引擎
content.js        内容脚本：监听划词、渲染浮层、滚动跟随
popup.html/js     工具栏弹层：开关、切换引擎、跳转完整设置
options.html/js   完整设置页：填凭据、选语言、测试引擎
LICENSE           MIT
README.md         本文档
dev/selftest.js   开发用自测脚本，不参与扩展运行
```

**关于 `config.js`**：`DEFAULTS` 只在这一个文件里定义，四个地方共用同一个文件——service worker 用 `importScripts`、content script 靠 manifest 里的加载顺序、设置页和弹层用 `<script src>`、Node 自测用 `require`。**加新配置项时只改这里**，不要往别的文件里塞拷贝。

**跑自测**（需要 Node，不影响扩展本身）：

```bash
node dev/selftest.js
```

它会 mock 掉 chrome API 和网络请求，验证引擎调度、凭据缺失处理、各类错误提示、以及 `quotaMode` 的分支行为，共 16 项。

> ⚠️ `selftest.js` 必须留在 `dev/` 子目录里。Chrome 不允许扩展目录中出现以 `_` 开头的文件名（`_locales`、`_metadata` 除外），一旦改名成 `_selftest.js` 放回根目录，扩展会**直接拒绝加载**。

**权限说明**（申请得很少，审核更容易过）：

- `storage`：在本机保存你的配置
- `host_permissions`：只包含两个翻译接口的域名，用于发请求
- 内容脚本匹配 `<all_urls>`：划词翻译必须能在所有网页上工作

## 七、路线与未做的部分

**变现路线**：先做「免费 + 用户自带 API Key」，看效果再决定是否做「平台托管额度」（用户不配置凭据、由本扩展的服务端代付）。

配置项 `quotaMode` 与 `background.js` 里的 `translateViaPlatform()` 就是为此预留的接缝：

- `quotaMode`：`'own'`（默认，当前唯一可用）/ `'free'`（弹层与设置页里已置灰）
- `translateViaPlatform()`：目前只抛「尚未开放」。将来接入托管后端时，**只需实现这一个函数**，设置页、配置存储、调度逻辑都不用动

**这一版没做的**：

- 手动模式：选中后先显示小图标，点击才翻译（现在是选中即翻译）
- 生词本 / 历史记录
- 整页翻译
- 发音朗读
- 快捷键自定义
- 图标文件（现在用 Chrome 默认图标）

**已移除**：百度翻译（v0.3.0 起）。旧实现含 MD5 签名算法，如需恢复可从 git 历史里取。

代码里引擎是按「一个引擎一个函数」写的，加新引擎只需在 `background.js` 里加一个函数、在 `runTranslate` 里加一行分支。
