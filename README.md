# 划词翻译

一个 Chrome 扩展（Manifest V3）：在任意网页选中文字，松开鼠标即可看到译文。

- 全部逻辑在本机运行，不经过任何第三方服务器（除了你选择的翻译引擎本身）
- 浮层用 Shadow DOM 封装，不会被网站自带的 CSS 弄乱
- 支持三种翻译引擎，设置页里切换
- 配置只存在本机，不跨设备同步

---

## 一、安装（开发者模式加载）

1. 打开 Chrome，地址栏输入 `chrome://extensions/` 并回车
2. 打开右上角的 **开发者模式**
3. 点左上角的 **加载已解压的扩展程序**
4. 选择本文件夹（`D:\eighteentang-translator`）
5. 安装完成后，点击工具栏里的扩展图标即可打开设置页

> 改了代码之后，回到 `chrome://extensions/` 点一下本扩展卡片上的刷新按钮，再刷新网页即可生效。

---

## 二、选一个翻译引擎

设置页里三选一，三个引擎都内置了。

> **本机实测结果（2026-09-23）**
>
> | 引擎 | 结果 | 说明 |
> |---|---|---|
> | Google 免费接口 | **不可用** | 通过代理返回 429，带真实 Chrome UA 后返回反滥用拦截页，换参数返回 403 |
> | 百度翻译 | 可达 | HTTP 200，耗时 0.45 秒 |
> | DeepSeek | 可达 | HTTP 401（未带 key 时的正常响应），耗时 0.65 秒 |
>
> 因此**默认引擎已设为 DeepSeek**。Google 那个选项仍然保留，换个代理节点后可能恢复。

### 方案 A：DeepSeek（默认，推荐）

1. 打开 DeepSeek 开放平台，注册并登录
2. 左侧菜单进入 **API keys**，创建一个，复制出来（只显示一次）
3. 充值（按量计费）
4. 把 key 填进设置页

- 优点：能结合语境翻译，不是逐词替换；境内直连稳定；注册流程最快，不需要实名认证
- 缺点：需要充值；响应比专用翻译接口慢（1–2 秒）

**成本参考**（依据 DeepSeek 官方定价页的 `deepseek-flash` 模型）：一次划词大约消耗 100 输入 + 50 输出 tokens，单次成本约 **0.0003–0.0006 元**。按每天 100 次计算，一个月不到 2 元。

> 代码里已经显式关闭了 DeepSeek 的思考模式。它默认开启且强度为 `high`，对翻译这种任务只会拖慢速度。

### 方案 B：百度翻译（境内直连稳定）

1. 打开百度翻译开放平台，注册并登录百度账号
2. 完成**个人实名认证**（免费额度需要认证后才能领取）
3. 在「管理控制台 → 开发者信息」里找到 **APP ID** 和 **密钥**
4. 开通「通用文本翻译」服务
5. 把 APP ID 和密钥填进设置页

- 优点：境内直连、延迟低（0.2–0.5 秒）、有免费额度
- 缺点：需实名认证；免费额度按字符数计算，**具体额度以官网当前页面为准**（政策调整过多次）
- 建议：在控制台里开启额度用尽提醒，避免产生意外扣费

### 方案 C：Google 免费接口

**不用填任何东西，但当前网络环境下用不了。**

- 优点：零注册、零成本、延迟低
- 缺点：非官方接口，对共享代理 IP 限流严格（本机实测稳定返回 429）；境内必须依赖代理
- 适合场景：你换到一个干净的代理节点、且确认能访问 `translate.googleapis.com` 时

## 三、怎么用

- 在任意网页**选中文字 → 松开鼠标**，选区旁会出现浮层显示译文
- 浮层上的按钮：**复制**（复制译文）、**关闭**
- 关闭方式：点「关闭」、按 `Esc`、点击页面空白处
- 页面滚动时浮层会跟随选区
- 选中的文字超过 1000 字符不会翻译（避免误选整页）
- 纯数字、纯符号不会触发翻译

## 四、常见问题

**选中后没有任何反应**

1. 先确认设置页里「启用划词翻译」是开着的
2. 到 `chrome://extensions/` 点本扩展的刷新按钮，然后**刷新网页**（必须刷新，否则旧的内容脚本还在跑）
3. 有些网站的阅读器模式或 PDF 阅读器里拿不到选区，属于浏览器限制

**浮层提示「扩展未就绪」或「扩展上下文已失效」**

扩展重新加载后，已经打开的网页里跑的还是旧脚本。刷新那个网页即可。

**提示网络请求失败**

- 用 Google 引擎：确认代理已开启且浏览器确实走代理。如果返回 429，说明这个公共接口对你的出口 IP 限流了——换个节点，或改用另外两个引擎
- 用百度 / DeepSeek：确认网络正常，以及设置页里的凭据填对了

**翻译报错**

把浮层上的完整报错文字发我，我按错误码定位。百度翻译的错误码含义以官方文档为准。

**改了设置不生效**

设置是即时生效的，但如果页面在改设置之前就打开了，建议刷新一次页面。

## 五、文件说明

```
manifest.json     扩展清单（MV3），声明权限、后台脚本、内容脚本
background.js     后台服务：按配置调用翻译引擎，内含 MD5 实现（百度签名需要）
content.js        内容脚本：监听划词、渲染浮层、滚动跟随
options.html      设置页结构
options.js        设置页逻辑：读写配置、测试引擎
README.md         本文档
dev/selftest.js   开发用自测脚本，不参与扩展运行
```

**跑自测**（需要 Node，不影响扩展本身）：

```bash
node dev/selftest.js
```

它会 mock 掉 chrome API 和网络请求，验证三个引擎的调度、百度签名算法、各类错误提示等 18 项。

> ⚠️ `selftest.js` 必须留在 `dev/` 子目录里。Chrome 不允许扩展目录中出现以 `_` 开头的文件名（`_locales`、`_metadata` 除外），一旦改名成 `_selftest.js` 放回根目录，扩展会**直接拒绝加载**。

**权限说明**（申请得很少，审核更容易过）：

- `storage`：在本机保存你的配置
- `host_permissions`：只包含三个翻译接口的域名，用于发请求
- 内容脚本匹配 `<all_urls>`：划词翻译必须能在所有网页上工作

## 六、这一版没做的（有意留空）

- 手动模式：选中后先显示小图标，点击才翻译（现在是选中即翻译）
- 生词本 / 历史记录
- 整页翻译
- 发音朗读
- 快捷键自定义
- 图标文件（现在用 Chrome 默认图标）

代码里引擎是按「一个引擎一个函数」写的，加新引擎只需在 `background.js` 里加一个函数、在 `runTranslate` 里加一行分支。
